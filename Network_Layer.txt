Network Layer Services:
1. Logical Addressing: host-to-host delivery and routing
2. Routing: create a forwarding table
3. Forwarding: sending to next hop
4. Fragmentation and Reassembly
5. Error Handling and Diagnostics: ICMP (Internet Control Message Protocol) - destination unreachable/ time exceeded
6. Quality of Service (QoS): priority provided to certain packets

- Devices:

Best Effort Service Model:
No guarantees on:
– successful datagram delivery to destination
– timing or order of delivery
– bandwidth available to end-end flow

Service Model Implementation:
1. IP Protocol: Packet Formatting and Addressing
2. Routing Protocol: RIP, OSPF, BGP (determine path)
3. ICMP Protocol: Error Reporting and Host Signalling
4. Forwarding Table (port to assign)

Services by Network Layer:

At Source:
1. Packetizing
2. Finding the logical address of the next hop
3. Finding the physical (MAC) address of the next hop
4. Fragmenting the datagram (if necessary)

At Router:
1. Finding the logical address of the next hop
2. Finding the physical (MAC) address of the next hop
3. Fragmenting the datagram (if necessary)

At Destination:
1. Reassembling the fragmented datagram (if necessary)
2. Delivering the datagram to the upper layer
3. Decapsulating the packet
4. Extracting the original data

Forwarding v/s Routing
- direct packet (from sender) to outgoing link | define whole path
- local scope | global scope
- hardware implementation | software implementation
- nano seconds | milliseconds

Routing Algorithms Classification
- Global (all routers have complete topology; USES 'LINK-STATE': RIP (ROUTING INFORMATION PROTOCOL)) and Decentralised (neighbour nodes are defined with cost known; USES 'DISTANCE-VECTOR': OSPF (OPEN SHORTEST PATH FIRST))
- Static (change slowly over time after several front and back) and Dynamic (change frequently: periodic and as per link cost change)

Features of Routing Algorithms:
- Correctness: always produce loop-free, valid routes
- Optimality: shortest / least-cost path based on the chosen metric
- Minimal Overhead: Lower computation and storage overhead
- Robustness (Fault Tolerance): Should handle link/node failures
- Stability: Converges to a stable state quickly after updates
- Scalable: Handle a large number of nodes

Intra and Inter-Domain Routing
- An internet can be so large that one routing protocol cannot handle the task of updating the routing tables of all routers. So, an internet is divided into autonomous systems.
- An autonomous system (AS) is a group of networks and routers under the authority of a single administration.
- Routing inside an autonomous system is referred to as intra-domain routing.
- Routing between autonomous systems is referred to as inter-domain routing.

Cost Metrics:
- Hop Count: Number of router between source and destination
- Bandwidth: prefer path with higher bandwidth
- Delay (Latency): used in EIGRP (Enhanced Interior Gateway Routing Protocol)
- Load
- Reliability: historical link stability (failure rate & error rate)

IP Address:
- Address designated to every device on the internet.
- 2^32 binary space separated into 4 bytes (octet configurations)
- Classful Addressing: placed into classes to identify class of address
- Class A: Net ID (1) and Host ID (3); Class B: Net ID (2) and Host ID (2); Class C: Net ID (3) and Host ID (1); Class D: Multicast Address; Class E: Reserved for future use;
- Network Mask: routers in the internet normally use an algorithm to extract a network address from destination address of the packet. 'n' leftmost bits are set to 1 and the remaining '32-n' are set to 0. Network masks have a block size of 2^(32-n). 
- In classless addressing, there isn't any fixed number of bits for net id and a slash notation is used to provide the value 'n'.
- Total number of addresses = 2^(32-n); First address starts from the first plausible value of mask with the block size (adding till the last address)
- Subnetting (Three level addressing): network portion; subnetwork portion; host portion
- Number of 1s represent Network and Subnet ID and 0s represent Host ID; unlike classful masking, subnet masks are needed to identify subnetwork.

NAT (Network Address Translation):
- Provides mapping between private and universal/global addresses.
- Private addresses: used for internal communication.
- Global address: at least one public Internet address used for communication with rest of world.
- Gateway/NAT router's public IP is globally visible; local endpoint IPs remain private.
- All datagrams leaving local network have same source IP as gateway.

Address Translation:
- Outgoing packet → NAT router replaces Source Address with global NAT address.
- Incoming packet → NAT router replaces Destination Address with private/local address.
- NAT maintains Translation Table: Private/Local Address ↔ Universal/Global Address.
- Translation process:
  1. Make table entry
  2. Change source address
  3. Access translation table
  4. Change destination address

IP DATAGRAM (IPv4 Header):
- Total datagram size: 20–65,535 bytes
- Header size: 20–60 bytes
- Fixed header: 20 bytes
- Variable part: Options + Padding (0–40 bytes)

IPv4 Header Fields:
Version: 4 bits
Header Length (HLEN): 4 bits
Service Type: 8 bits
Total Length: 16 bits
Identification: 16 bits
Flags: 3 bits
Fragmentation Offset: 13 bits
Time To Live (TTL): 8 bits
Protocol: 8 bits
Header Checksum: 16 bits
Source IP Address: 32 bits
Destination IP Address: 32 bits
Options + Padding: 0–40 bytes

Service Type:
- 8 bits
- TOS bits: D = Minimize Delay; T = Maximize Throughput; R = Maximize Reliability; C = Minimize Cost
- Precedence subfield: part of IPv4 but never used
- Used to indicate desired service characteristics.

FRAGMENTATION:
- Datagram can travel through networks having different MTUs.
- Router: decapsulates IP datagram → processes it → encapsulates it into another frame.
- Frame format/size depends on physical network protocol.
- MTU = Maximum Transfer Unit.
- Ethernet MTU = 1500 bytes
- FDDI MTU = 4352 bytes
- PPP MTU = 296 bytes
- Datagram size must be ≤ MTU.
- If datagram > MTU → fragmented.
- Each fragment gets its own header; most fields repeated, some changed.
- A fragment can itself be fragmented if next network has smaller MTU.
- Datagram may be fragmented multiple times before reaching destination.
- Required header parts are copied into every fragment.
- Only data is fragmented.

Fragmentation Fields:
1. Identification: 16 bits
   - Identifies datagram originating from source host.
   - Identification + Source IP uniquely identify a datagram leaving source.
   - Same Identification value is copied into all fragments.
   - Fragments with same Identification are assembled into one datagram.

2. Flags: 3 bits
   - 1st bit: Reserved
   - 2nd bit: DF (Don't Fragment)
     - DF=1 → datagram must not be fragmented; if it cannot pass → discard.
     - DF=0 → datagram may be fragmented.
   - 3rd bit: MF (More Fragments)
     - MF=1 → more fragments follow.
     - MF=0 → last/only fragment.

3. Fragmentation Offset: 13 bits
   - Position of fragment data relative to original datagram.
   - Measured in units of 8 bytes.
   - First byte number = Fragment Offset × 8.

Fragmentation Numericals:
- M=0 → last fragment OR non-fragmented packet; cannot determine whether original was fragmented.
- Offset = 100 → first byte = 100 × 8 = 800.
- Example: First 8 bits = 01000010
  - Version = 0100 = 4 → correct
  - HLEN = 0010 = 2 → header length = 2×4 = 8 bytes
  - Minimum IPv4 header = 20 bytes → corrupted/invalid packet → discard.
- Example: 45000028000100000102...
  - TTL is 9th byte = 01
  - Packet can travel only 1 hop.
- Fragmentation example:
  A→B MTU=520, B→C MTU=320, C→D MTU=270
  Original data = 1000 bytes; IP header = 20 bytes
  A→B payload = 500 bytes.

CHECKSUM:
- IPv4 checksum covers ONLY the header, not data.
- Reasons:
  1. Upper-layer protocols already have checksum covering whole packet.
  2. IP header changes at every router; data does not.

OPTIONS:
- IPv4 header consists of fixed part + variable part.
- Fixed part = 20 bytes.
- Variable part = Options; maximum 40 bytes.
- Options are NOT required.
- Used for network testing and debugging.

IPv6:
- Address = 128 bits = 16 bytes.
- Dotted-decimal notation is too long.
- Colon Hexadecimal Notation used for readability.
- 128 bits divided into 8 sections, each 16 bits (2 bytes).
- Example format: FDEC:BA98:7654:3210:ADBF:BBFF:2922:FFFF

IPv6 Desirable Features:
- Supports billions of hosts
- Faster processing at routers
- Supports real-time applications
- Provides security
- Multicast support
- Mobility support

IPv4 v/s IPv6:
IPv4 | IPv6
32-bit address | 128-bit address
Dotted decimal | Hexadecimal
2^32 = 4,294,967,296 addresses | 2^128 addresses
Class-based addressing | Classless addressing
Deployed: 1981 | Deployed: 1999

IPv4 Header v/s IPv6 Header:
IPv4 Header Length → Eliminated in IPv6; fixed header length
IPv4 Service Type → Traffic Class + Flow Label
IPv4 Total Length → Payload Length
IPv4 Identification + Flags + Fragment Offset → Fragmentation Extension Header
IPv4 TTL → Hop Limit
IPv4 Protocol → Next Header
IPv4 Header Checksum → Eliminated
IPv4 Options → Extension Headers

What's missing in IPv6:
- No checksum → faster router processing
- No fragmentation/reassembly at intermediate nodes → performed at source
- No options in base header → handled using extension/next-header mechanism

IPv6 Traffic Class:
- Default/Best-Effort (BE): DSCP = 000000 = decimal 0
  - Normal traffic; e.g., web browsing, email.
- Expedited Forwarding (EF): DSCP = 101110 = decimal 46
  - High-priority, low-latency traffic
  - Used for VoIP, video conferencing, online gaming

ROUTERS:
- Layer-3 relay operating at Network Layer.
- Can link two dissimilar LANs.
- Isolates LANs into subnets to manage/control network traffic.
- 4 basic components:
  1. Input Ports
  2. Output Ports
  3. Routing Processor
  4. Switching Fabric

ROUTER ARCHITECTURE:
- Routing Processor:
  - Routing + management
  - Control Plane
  - Software
  - Operates in millisecond time frame
- Switching Fabric:
  - Forwarding/Data Plane
  - Hardware
  - Operates in nanosecond time frame
- Input Ports → Switching Fabric → Output Ports

Input Port:
- Performs Physical Layer + Data-Link Layer functions.
- Contains buffer to hold packet before forwarding to switching fabric.

Output Port:
- Performs same functions as input port, but in reverse order.

Routing Processor:
- Performs Network Layer functions.
- Performs table lookup.

Switching Fabric:
- Moves packet from input queue → output queue.
- Uses specialized mechanisms.
- Realized using multistage interconnection networks.

ROUTING TABLE:
- Longest Prefix Matching:
  - For a given destination address, choose forwarding-table entry having the longest matching address prefix.

ROUTER FUNCTIONALITY:
Upon receiving a packet:
1. Lookup forwarding table
2. Update destination MAC address
3. Decrement TTL
4. Forward packet to output port
